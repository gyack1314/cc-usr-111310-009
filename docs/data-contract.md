# 多父组织层级

edge方向child->parent。每个有父节点出边权重和必须精确为1，root无父边；所有节点包括无事实的孤立root保留。权重用有理数字符串，不能以浮点容差接受非1。零权边不贡献但仍属结构环检测。self桥weight=1。祖先权重累加所有路径乘积，不对祖先个数归一。

leaf经left和right两路到rootA，旧权重3/4到A、1/4到B；value100贡献75/25，负20贡献-15/-5。right换为1/4到A、3/4到B后leaf变5/8及3/8。只有显式rebind的f1变更，f2/f3仍hv1。null是事实存在但数值缺测，不按0凑守恒；可加数值单独守恒，缺测计数亦报告。

selected_rollup_nodes如有祖先关系或共享任何事实后代，报告不可直接加，除非它们是互不重叠的根集合且能证明覆盖。路径明细可作小基准，正式桥可动态规划压缩，同一root从多路径来需相加。初始工具不算闭包和事实分摊。

# 版本化层级、桥与重挂实现约定

## 层级清单

`kind` 为 `weighted-hierarchy`。`nodes` 为节点名数组（不得重复）；`edges` 为
`{child,parent,weight}` 数组。方向固定 `child -> parent`，因此“反向后代”指沿
父到子方向可达的节点。权重必须是正则 `^[0-9]+(?:/[0-9]+)?$` 的非负有理数字符串，
经 `fractions.Fraction` 解析，不接受浮点、负数、空白、`1/0` 或多重斜杠；分母为 1
时序列化为整数形式。

拒绝顺序为：身份/重复节点 → 未知节点/重复边/自环 → 权重语法 → 每个非根节点父权重
和精确为 1 → 结构环（零权边同样参与环检测）。根是没有任何父边的节点；根可以多于
一个，孤立根保留。中间层深度不固定。

## 桥

每个层级版本都带完整桥：对每个 `(source, ancestor)` 保存精确权重、全部简单路径
证据（节点序列 + 路径乘积）和 `computed_in`（该行实际由哪个版本计算）。`source`
到自身权重恒为 1，路径为 `[source]`。祖先权重是所有有向路径乘积之和：菱形汇合时
多路径相加，不取最短路径、不对可达祖先均分。同一路径证据之和必须等于桥权重。

独立参考：`Hierarchy.verify_bridge()` 从每条边重新枚举全部简单路径，逐条对照
动态规划桥的路径集合、路径乘积、路径和与桥权重。`computed_in` 表示重算来源而
不是当前版本：新层级的复用节点保留父版本的 `computed_in`。

## 事实分摊

事实对象字段为 `fact_id`、`node`（原始叶/节点）、`value`、`hierarchy_version`。
`value` 只能是 JSON 整数或 `null`；`null` 表示事实存在但数值缺测，分摊时每条贡献
的 `contribution` 保持 `null`，不按 0 补。负值表示冲正，正常乘以桥权重。
`allocate_fact` 只接受与事实 `hierarchy_version` 相同的层级；多版本混用时逐事实
选桥。每个可加事实的根贡献之和必须精确等于事实值，失败拒绝。

`assess_rollup` 同时检查：选中节点在每个相关版本里都是根；选中节点间没有祖先/
后代关系；每个事实流向选中根集合的桥权重和为 1。三条件同时成立才输出
`group_total`。其它选择最多给 `candidate_unqualified_sum` 和逐节点数字，并列出
`ancestor_pairs`、`overlap_facts`（共同下游事实）、`uncovered_facts` 与原因，绝不
把中间层或部分根集合的贡献称为集团总量。无事实的孤立根贡献为 0，可一并选中而不
改变总量。缺测事实单独计数，不参与数值守恒。

## 局部改权与新版本

`Hierarchy.successor(base, version, edge_updates)` 只允许修改既有边（不能新增边、
不能重复改同一条边），改后仍要求每个非根节点权重和为 1 且无环，并必须至少有一条
实际权重变化。实际改权的子节点集合的“反向后代闭包”沿父 -> 子方向枚举，包含子节点
自身；只有闭包内节点重建桥，闭包外节点原样复用父版本行（`computed_in` 指父版本）。
菱形汇合时改一个分支会同时重算另一分支汇合后的下游，不会只重算一条边。

## 仓版本提交

`commit_warehouse(path, warehouse_version, hierarchy, facts, base_hierarchy=..., rebind=...)`
生成一个 JSON 文档，包含 `hierarchies`（旧层级、新层级，各带边、根、完整桥和摘要）、
`facts`（最终事实）、`rebind`（计划与差额）。重挂计划绑定：旧层级摘要、新层级摘要
（含新层级 summary/digest）、旧事实集合摘要、被重挂事实子集摘要、`fact_id` 列表、
未重挂列表。差额逐事实逐祖先给出旧/新权重、旧/新贡献和 `delta`（缺测事实三项均
为 `null`）。

提交顺序：先在内存构造并完整重算核对（含桥与事实版本一致性），再写同目录临时文
件、`fsync`、单次 `os.replace`、目录 `fsync`；任何异常删除临时文件，旧文档不变。
`verify_warehouse` 会重算每个层级的桥与每个差额，并确认事实恰为“旧事实集合中被
重挂者切到新版本”的结果；检测到新桥配旧事实、旧桥配新事实、篡改差额/缺测值/摘要
均拒绝写入或读取。

## 已知边界

`structural-cycle.json` 的结构环在层级装载阶段被拒绝，因此不能产生桥或汇总；
`invalid-config.json` 的重复节点同样在装载阶段拒绝。其余清单可装载，是否可直接
相加由 `selected_rollup_nodes` 的业务含义决定，不自动修正层级形状。
